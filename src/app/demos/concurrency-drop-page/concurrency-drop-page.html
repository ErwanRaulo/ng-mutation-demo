Two independent mutation() instances charge a card, side by side — one with no concurrency option, one with concurrency: 'drop'. The fake server takes 1.5 seconds to answer (an artificial delay, to leave time for a second click).

Pay

Try it: double-click "Pay". The button is deliberately not disabled while pending, to show what each mutation does with a second click on its own.

Each click starts its own request, and both reach the server: a double-click charges the card twice.

concurrency: 'drop'

mutation.status()
{{ payDrop.status() }}
mutation.value() — charges recorded by the server
@if (payDrop.hasValue()) { {{ payDrop.value().length }} charge(s) of {{ amount }} € } @else { no charge yet }

While a charge is in flight, the second click is dropped: mutationFn is not called and the signals are left untouched, and that mutate() rejects with an AbortError whose message is 'Dropped'. The card is charged once. A new click is accepted as soon as the charge settles (or after reset()).
