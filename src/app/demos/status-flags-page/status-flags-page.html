isIdle/isSuccess/isError are derived straight from status() — sugar for status() === 'success' and friends, so templates read as booleans instead of string comparisons. Compare with isPending, which already existed.

Rendered from the flags directly

@if (createUser.isIdle()) {

Idle — nothing created yet.

} @if (createUser.isPending()) {

Pending…

} @if (createUser.isError()) {

{{ createUser.error() }}

} @if (createUser.hasValue()) {
{{ createUser.value().name }} #{{ createUser.value().id }}
}

isSuccess() itself doesn't narrow value() — that's what hasValue() is for, see the card above. The two are complementary: one tells you the status, the other narrows the type.

Exactly one of the four flags is true at any time — they don't add new state, just a friendlier read of status().
